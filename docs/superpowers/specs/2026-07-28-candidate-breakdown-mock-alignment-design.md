# 交換候補と計算内訳のモック整合

## 目的

交換候補とノリ打ちの計算内訳を、承認済み精密モックと同じ情報順・着色位置・背景・余白へ合わせる。

## 交換候補

候補は常に次の4行を表示する。

1. 現在の達成目標より1段上
2. 現在の達成目標
3. 現在の達成目標より1段下
4. 現在の達成目標より2段下

2行目だけを達成行として淡いスレート背景で強調する。1行目に強調色を付けない。必要枚数、交換額、景品の列幅・文字色・罫線・行高はモック値へ揃える。単位と長い景品内訳の折り返しもモックと同じ扱いにする。

## 計算内訳

DOMはモックと同じ `group-totals` と `group-table` を用いる。

総投資・総回収・収支のKPIセルには個別の白背景を付けず、計算内訳セクションの紙色を透過して見せる。見出し色、数値色、罫線色は既存の鉛筆スレートトークンを使う。

余白は次の値へ揃える。

- KPI下: 16px
- 表下: 24px
- セクション内側: 上下24px、左右16px
- 表セル: 上下12px、左右4px

## 非対象

交換計算、ノリ打ち配分、受け渡し計算、入力値、ブラー、条件保存は変更しない。

## 検証

- 候補が「上1・達成・下2」の順で生成され、2行目だけ強調されることを確認する。
- KPIセルが透明であること、余白とクラス構造がモックと一致することをDOM契約テストで確認する。
- 同じ入力条件を使い、320pxでモックと実装の候補・計算内訳の寸法とcomputed styleを比較する。
- 375px、414pxで横あふれがないことを確認する。
