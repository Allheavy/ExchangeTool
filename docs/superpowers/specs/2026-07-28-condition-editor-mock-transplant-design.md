# 条件編集画面のモック移植

## 目的

スマホ版の条件編集画面から旧式の選択UIを外し、承認済み精密モックと同じ情報構造・操作順へ置き換える。

## 画面構成

編集画面は全画面表示とし、次の順に配置する。

1. 戻るアイコンと「条件を変更」見出し
2. 種別
   - 任意入力の貸し出しレート
   - パチンコ／パチスロ選択
3. 交換率
   - 100円あたりの玉数または枚数
4. 景品
   - 管理画面に登録された景品額の複数選択
5. 「この条件を反映」ボタン

貸し出しレートと遊技タイプは同じ行に置く。景品額は3件を基本表示とするが、登録数が増えた場合は折り返す。

## 通常変更とPreset追加

通常の「変更」では条件だけを編集し、反映時に交換画面へ戻る。

Presetの追加ボタンから開いた場合も同じ編集UIを使う。ただし、景品の下にPreset名の任意入力欄と保存説明を追加し、最下部ボタンを「Presetとして保存」に変更する。空欄時は既存ルールで表示名を自動生成する。

## データ接続

新しいUIは既存の内部設定値へ変換してから、現在の交換計算・保存・Preset管理処理を呼ぶ。計算ロジック、保存キー、既存Presetの読み込み互換性は変更しない。

パチンコ／パチスロの切り替え時は交換率の単位だけを玉／枚へ更新し、入力済みの数値を不用意に消さない。

## 入力検証

- 貸し出しレートと交換率は正の数を必須とする。
- 景品は1件以上を必須とする。
- エラーは該当セクション内に表示し、画面を閉じない。

## 検証

- DOM契約テストでモックの見出し、1行配置、入力、景品、反映ボタンを確認する。
- 通常変更で交換計算と条件表示が更新されることをブラウザで確認する。
- Preset追加時のみ名前欄が表示され、保存後にPreset行へ追加されることを確認する。
- ブラー、既存Preset、管理画面、オフラインキャッシュを回帰確認する。
- 320、375、414pxで横あふれと操作不能な要素がないことを確認する。
