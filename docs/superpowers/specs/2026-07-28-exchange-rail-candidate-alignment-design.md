# 交換レールと候補表示のモック整合

## 目的

スマホ版の交換画面を承認済み精密モックへ合わせ、目標枚数の確認から持ち玉の再入力までを一操作にする。

## 対象

- 持ち玉入力から現在位置の丸へ伸びる接続線
- 達成目標・次の目標に表示する枚数と単位
- 目標タップによる持ち玉の置換と再計算
- 交換候補の列幅、強調、余白、単位
- Preset追加ボタンの垂直位置

ブラー、条件保存、Preset管理、交換計算の方式は変更しない。

## UI設計

レールは承認済みモックと同じ固定三点構成とする。持ち玉入力欄の下端中央から、レール中央の「現在」点まで細い縦線を接続する。線は情報を増やさず、入力値と現在位置が同一であることだけを示す。

左右の目標はタップ可能な一つの操作面とし、「達成目標／次の目標」「数値」「枚または玉」をまとめて表示する。差分表示より目標枚数を強く、単位は数値より弱くする。値がない目標は無効化し、タップできるように見せない。

交換候補はモックと同じ4行（上1・達成・下2）を維持する。達成行のみ淡い背景で強調し、必要枚数には単位を表示する。内訳は `5,000×6 + 1,000×1` のように簡潔にする。

Preset追加ボタンはPresetチップと同じ行の中央に揃える。横スクロール領域から独立させ、スクロールバーやチップ件数で上下位置が変わらないようにする。

## 操作とデータフロー

達成目標または次の目標をタップすると、その目標枚数を持ち玉入力へ設定する。その後、通常の持ち玉入力と同じ `input` 更新経路を通して再計算・表示更新・保存を実行する。独自の計算経路は追加しない。

## アクセシビリティ

目標はネイティブの `button` とし、目標種別と設定される枚数を読み上げ可能にする。利用できない目標は `disabled` にする。接続線は装飾として読み上げ対象外にする。

## 検証

- DOM契約テストで目標ボタン、単位、接続線、Preset追加ボタンの配置契約を確認する。
- ブラウザで両目標をタップし、持ち玉と計算結果が更新されることを確認する。
- 320、375、414pxでモックと比較し、交換候補とPreset行に横あふれがないことを確認する。
- ブラーと条件保存が引き続き動作することを回帰確認する。
